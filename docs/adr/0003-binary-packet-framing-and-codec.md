# 0003 协议封包滑动窗口分帧与编解码状态机

神仙道底层协议基于裸 TCP 流传输，存在频繁的 TCP 粘包与半包分片，且服务端为了节省带宽，对大于特定阈值的数据帧混合启用了 RFC 1950 zlib 压缩；本项目决定在网络层实现基于滑动窗口的有限状态机 (`FrameFSM`)，严格采用 4 字节大端整数长度前缀切分数据帧，并实时嗅探魔数签名（`0x78` 配合特定标记字节）自动触发解压缩，上层配合大端序 `ByteArrayReader` / `ByteArrayWriter` 进行结构化反序列化；该设计彻底规避了流式解包错位导致的连接断开与脏数据传播。

## Status

accepted

## Considered Options

- **选项 1：滑动窗口状态机 + 长度前缀切分 + zlib 动态嗅探（采纳）**：内存缓存动态收缩并限制单帧上限（2MB），具备坏帧向前滑动自愈容错能力，完美透明处理压缩与非压缩混部封包。
- **选项 2：固定读取长度与同步阻塞解码**：在网络抖动或半包到达时极易发生读取阻塞或反序列化异常崩溃。
- **选项 3：通用第三方 RPC 框架抽象（如 Protobuf/Thrift 适配器）**：神仙道协议具有独特的 Mod/Act 双短整型头与 Flash ByteArray 特性，引入通用 RPC 框架会造成额外包装损耗且难以适配变长 zlib 压缩逻辑。

## Consequences

- 解码性能优异，在长时间大流量测试下无内存泄漏或解包漂移；
- 所有上层业务任务无需关心底层粘包、半包与压缩细节，直接面向透明解压后的标准载荷编程。
