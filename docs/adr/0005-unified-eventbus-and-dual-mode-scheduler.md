# 0005 统一事件总线与双模任务调度器

挂机脚本既需要支持系统 Crontab 定时调起执行完即退出的单次巡检（`--once`），又需要支持 24 小时常驻后台运行并响应服务端异步推送广播（`--daemon`），传统单体顺序脚本无法兼顾这两种生命周期；本项目决定采用集中式无状态 `GameContext` 维护角色与环境数据，引入发布-订阅模式的 `EventBus` 广播服务端推送帧，并设计支持周期任务与单次任务解耦编排的 `TaskScheduler`；该架构使单次巡检和长期常驻共享同一套任务与网络基础设施，保证代码高度内聚与复用。

## Status

accepted

## Considered Options

- **选项 1：Context + EventBus + TaskScheduler 双模编排架构（采纳）**：心跳等高频常驻协程与日常福利业务链解耦，`--once` 跑完日常福利链后优雅停机，`--daemon` 常驻模式持续监听广播并由调度器定期重入。
- **选项 2：单体线性脚本与全局 sleep 轮询**：代码严重面向过程堆砌，无法并发维护心跳，网络一旦波动全局阻塞死锁。
- **选项 3：引入重量级外部调度引擎（如 Celery / APScheduler）**：增加了庞大的外部依赖与部署难度，背离轻量级单文件可执行的极简哲学。

## Consequences

- 任务编写完全插件化，新增任何玩法只需继承 `BaseTask` 并实现 `execute` 方法；
- 状态变更通过 `EventBus` 单向流动解耦，服务端突发的被动广播（如玩家升级、系统下线公告）不会干扰主动发包队列。
