# 元宝与铜钱资产收支流水及每日汇总架构决策

## 背景与问题

神仙道官方服务端未提供可直接查询历史收支账单的协议接口。此前 Web 控制台展示的 7 日资产历史依赖纯线性递减的伪数据（Mock），且用户无法了解每日自动化运转中元宝与铜钱的具体收入去向、支出损耗及离线手操变动。我们需要在无侵入、不阻塞长连接主循环的前提下，实现 100% 账目平衡的实时收支流水记账与按日汇总。

## 架构决策

1. **差值驱动与双轨动态归因**：
   - 监听服务端权威数值广播 `Mod 0 Act 3 (PlayerUpdatePlayerDataResp)`，通过当前余额与前序基准计算实时差额（`delta = new_val - old_val`）。
   - 在 `GameContext` 中维护活动任务生命周期切片（`active_task_name`）。若差额产生于自动化日常/战斗期间，业务来源精准归因为对应玩法名称（如“仙府药园收获”、“招财神符”、“普通副本扫荡”等）；若差额产生于上线重连或空闲期，则自动归因为“微端/外部变动”或“被动收益”，确保全天每一笔收支皆有账可查。

2. **两层分级存储与生命周期**：
   - 在角色私有数据库（`storage_{server_id}_{player_id}.db`）中新增 `tb_asset_transaction`（明细流水表，按 2,000 条 FIFO 自动滚动淘汰）；
   - 新增 `tb_daily_asset_summary`（每日汇总表，按自然日记录期初、期末、元宝/铜钱总收入与总支出，永久保留）；
   - 采取流式即时增量更新（Stream-driven Upsert），每笔流水写入时同步原子累加当日汇总，杜绝定时跑批带来的跨天断档隐患。

3. **Web 全景态势集成**：
   - 彻底移除 `web/routes/telemetry.py` 中的伪数据生成逻辑，直连读取 `tb_daily_asset_summary` 近 7 日真实资产走势；
   - 升级 Web 控制台右侧抽屉面板，集成今日收支 KPI 概览与按日流水明细折叠时间线，提供元宝与铜钱分类筛选。

## 评估与备选方案

- **侵入式业务埋点（已否决）**：仅在各个任务回包处单独记录增量。该方案无法捕获世界 Boss 排行、全服补偿邮件、微端手工强化/消耗等外部被动变动，必然导致总账与实际余额发生漂移。
- **纯日终定时批处理汇总（已否决）**：依赖每日凌晨 00:00 的 Cron 触发。若账号在该时段处于防互踢避让或离线，将导致当日汇总漏记。流式即时 Upsert 具备更强的自愈容错能力。
