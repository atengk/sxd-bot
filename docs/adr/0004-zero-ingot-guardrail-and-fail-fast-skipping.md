# 0004 零元宝安全熔断机制与前置卫语句跳过策略

挂机脚本若因协议逆向偏差、活动冷却时间未到或参数校验错误向服务端发起付费动作请求，极易误损用户的元宝资产，甚至因在非活动时段发送畸形指令触发网关安全熔断被强制踢下线（EOF）；本项目决定在框架内核中树立“严格零元宝”核心红线，对任何存在元宝消耗分支的协议指令实施客户端前置硬拦截，并对时段性/门槛性玩法（如世界 Boss、多人副本、低等级未解锁功能）采用快速失败前置卫语句跳过 (`SKIPPED`)；此举从架构底层彻底消除了误扣资产风险与非活动时段误发指令导致的断连。

## Status

accepted

## Considered Options

- **选项 1：客户端内核级参数硬拦截 + 任务前置条件卫语句（采纳）**：在业务发包前校验免费状态与等级/时段前置条件，不满足时返回 `TaskResult.skipped()`，零网络发包，零元宝风险，零服务端异常断开。
- **选项 2：依赖服务端回包错误码容错**：盲目发送请求并根据服务端报错处理，不仅浪费网络开销，且神仙道部分模块对非活动期发包极为敏感，直接判定外挂并断开 Socket。
- **选项 3：可配置的元宝消耗上限策略**：允许用户配置小额元宝消耗，但逻辑分支极复杂，一旦配置失误或版本差异可能导致灾难性元宝清空。

## Consequences

- 绝对保障了使用者的账号核心资产安全；
- 各任务模块具备统一规范的生命周期状态返回 (`SUCCESS`, `FAILED`, `SKIPPED`)，便于 CLI 美化输出清晰审计结果。
