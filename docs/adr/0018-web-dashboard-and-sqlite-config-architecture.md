# 0018. Web 控制台控制架构与 SQLite 配置仓储规范

- **状态**: Accepted
- **日期**: 2026-10-16
- **作者**: Ateng

## 背景与上下文

神仙道无头协议自动化系统从单机短生命周期 CLI 工具向现代化多账号 Web 运行态演进。在引入 Web 控制台时，面临玩家手动上号被挤下线（双端互踢冲突）、多账号细粒度日常策略差异、配置并发写入数据竞争，以及 CLI 与 Web 双进程连接冲突等关键挑战。

## 架构决策

1. **常驻连接池与防互踢避让状态机**:
   - Web 服务采用 FastAPI 常驻常态守护进程，为启用的账号维护 TCP 长连接与心跳保活；
   - 引入**防互踢避让 (Mutual Evade)**机制：底层协议栈检测到服务端下发的顶号/被踢通知包时，立即自动挂起重连定时器，进入避让状态并在 Web 标黄展示；支持 Web 手动恢复与基于**静默探测恢复 (Silent Probe Recovery)**的冷却探活双轨策略。
2. **纯 SQLite 配置仓储 (SQLite Config Store)**:
   - 全面由 `data/config.sqlite` 独立纳管配置，彻底废除对 `config.json` 的主依赖；
   - 支持多账号凭据、账号级独立 35 项日常子任务启停开关、元宝安全红线与 Web 访问密钥的 ACID 事务持久化。
3. **中央服务代理模式 (Central Daemon Proxy)**:
   - Web 进程作为多账号网络长连接的单一权威宿主；CLI 命令行工具改造为调用 Web API 的客户端，消除多进程重复登录导致的游戏内互踢与 SQLite 锁冲突。
4. **轻量内嵌 SPA 与 SSE 流式事件**:
   - 前端采用内嵌单页架构（Tailwind CSS + Vue 3 / Alpine.js），由后端单端口挂载托管，零 Node.js 编译工具链依赖；
   - 任务进度与控制台日志基于 SSE (Server-Sent Events) 单向推流，支持按账号别名多标签过滤；
   - 访问入口采用轻量 Passphrase Token 门禁验证。

## 方案权衡与影响 (Consequences)

- **正面收益**:
  - 彻底终结玩家手动打游戏时被自动化程序顶号互踢的恶劣体验；
  - 容器化单数据卷映射（只需挂载 `/app/data` 即可持久化所有配置与快照）；
  - 账号级日常策略高度客制化，小号大号各司其职。
- **代价与权衡**:
  - CLI 命令行操作依赖 Web 宿主处于运行状态（通过轻量 HTTP 桥接调度）；
  - 需针对协议层顶号包精准提取 opcode 映射以保障避让触发的 100% 可靠性。
