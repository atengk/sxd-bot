# 27. 全域综合福利收割、练功修行闭环、自适应盲测解包与果园即时采摘体系决策

## 状态
已接受 (Accepted) - 2026-10-17

## 背景与问题陈述
在对大号真实游戏状态、微端界面截屏及底层官方协议逆向字典（`data/protocol_manifest.db`）对比审视中，发现了 7 项影响日常收益闭环与数值展示精度的核心缺陷：
1. **体力数值展示存在时延脱节 (109 vs 1)**：大号刚登录时基础体力快照为 1，随后游戏端结算离线体力 (+108) 升至 109；但 Web 控制台因未接入属性变更 SSE 事件流且无轮询刷新，显示滞留于初始的 1。
2. **【领取奖励】面板福利截留 (图1)**：游戏底部导航栏【领取奖励】涵盖竞技场每日声望/铜钱、全服超级礼包 (Mod 2 Act 6/29) 以及幸运日免费祈福/随机抽取，此前未被自动化流水线纳管。
3. **练功打坐经验未结算签收 (图2)**：角色城镇挂机打坐已累积 25.48 亿经验，现有 `PracticeTask` 仅执行发起打坐 (Mod 0 Act 36)，从未调用签收经验协议 (Mod 0 Act 38)。
4. **仙道问灵求签后奖励未领取**：`AskFairyTask` 仅执行求签指令 (Mod 503 Act 3)，未带入求签结果调用领取签文与奖励协议 (Act 4/1)。
5. **版本更新福利未领取**：官方版本维护与补丁福利模块 (`Mod 240: ReleaseWelfare`) 完全缺失自动化支持。
6. **背包宝箱与可用物品被跳过**：大号背包物品绝大部分为通用类型 (`item_type = 11`) 且命名为 `道具 #ID`，此前基于中文名称关键字（“箱/盒/袋”）的过滤规则直接将其漏判。
7. **药园巡检延迟与果园体系缺失**：药园巡检延迟至托管 180 秒后才首发；且家园仙树（摇钱树/仙令树）与蟠桃园摘仙桃 (Mod 40) 未与药园形成协同。

## 决策内容

### 1. 角色属性瞬态变更 SSE 实时流推送到端 (Real-time Attribute Streaming)
- 在 `network/client.py` 捕获到角色数值变更广播 (`Mod 0, Act 3: update_player_data`) 时，不仅更新本地上下文与数据库，同时向 EventBus 广播 `ACCOUNT_DATA_UPDATED` 事件；
- 前端通过 SSE 监听该事件，就地无感 patch 更新账号卡片的 `power`、`coins`、`ingots`、`level` 数值，达成 0 刷新、0 闪烁的实时同步。

### 2. 每日领奖总管任务 (`TakeAwardTask`)
- 统筹收割【领取奖励】窗口全部合法白嫖收益：
  1. 调用 `Mod 2, Act 6` (`get_player_gift_all_info`) 拉取全部超级礼包，循环调用 `Mod 2, Act 29` (`player_get_super_gift`) 清空待领大礼；
  2. 结算竞技场每日排名声望与铜钱奖励 (`Mod 20, Act 1: pk_award` / `Mod 28`)；
  3. 巡检幸运日各子项目，执行每日免费祈福与随机抽取（古皇宿照、龙鱼仙令、灵脉、聚灵等），严格恪守 0 元宝安全红线。

### 3. 练功修行签收结算与无缝续练 (`PracticeTask` 升级)
- 在日常巡检与长连接建立时，先调用 `Mod 0, Act 37` (`get_practice_data`) 查询当前累积挂机经验；
- 若存在累积经验或修行时间，调用 `Mod 0, Act 38` (`sign_finished_practice`) 将数十亿挂机经验签收入账；
- 签收后立即调用 `Mod 0, Act 36` (`start_practice`) 重新进入城镇打坐状态，确保挂机收益不断档。

### 4. 仙道问灵求签与奖励闭环 (`AskFairyTask` 升级)
- 执行每日免费问灵 (`Mod 503, Act 3: do_ask_fairy`) 后，直接调用 `gain_ask_award` (`Mod 503, Act 4`) 领走当次签文资产与活跃度；
- 同步调用 `gain_recall_award` (Act 1) 与 `gain_ask_level_award` (Act 7)，保持兑换商店自选由玩家端内操作的零误触防线。

### 5. 版本更新福利自动化纳管 (`ReleaseWelfareTask`, Mod 240)
- 新增日常子任务 `ReleaseWelfareTask`：
  - 调用 `Mod 240, Act 0` (`get_info`) 同步更新福利状态；
  - 自动领取版本更新礼包 (`Act 1: get_welfare`)、额外元宝补偿 (`Act 3: get_extra_ingot`) 与版本专属大奖 (`Act 4: get_release_extra_award`)。

### 6. 背包自适应协议盲测解包流水线 (`item_clean.py` 升级)
- 废除对道具中文名称的死板依赖：
  1. 优先尝试自选宝箱探测 (`Mod 2, Act 159: player_use_grid_item_need_choose`)，若为自选箱直接调用 `Mod 2, Act 160: use_choose_box` 默认选取首个选项自动开启；
  2. 对背包内消耗品/礼包道具（`item_type` 为 2 或 11），调用大容量/单件使用指令 (`Mod 2, Act 130: large_use_grid_item` / `Act 23: player_use_grid_item`)；
  3. 服务端返回成功则物品开启入账；若返回不可使用或属于合成材料，则标记并转入仓库/变卖管线。

### 7. 药园握手即巡检与“果园”双模收割
- **握手即巡检**：长连接建连成功后，不再等待 180 秒，立即前置触发首轮药园收种、小助手领奖与果园采摘；
- **果园双模采摘**：
  - 药园仙树（Mod 13）：巡检仙令树 (`Act 18/20`) 与摇钱树 (`Act 12/13`) 免费采摘；
  - 蟠桃园仙桃（Mod 40）：执行偷桃/摘仙桃任务 (`GetPeachTask`)，挑战猴王获取海量角色经验。

## 影响评估
- **收益覆盖**：全面收割日常漏领盲区（挂机数十亿经验、全服超级礼包、更新补偿元宝、自选宝箱及仙桃经验）。
- **用户感知**：前端卡片体力/资产秒级响应（SSE 局部推流），彻底消除 109 vs 1 的滞后困惑。
- **稳定性**：所有福利抽取与宝箱开启严格守住 0 元宝消耗与安全降级底线。
