# 24. 强杀式避让、长连接全量默认启用与激进背包清空流水线架构决策

## 状态
已接受 (Accepted) - 2026-10-16

## 背景与问题陈述
在前期落实防互踢避让与背包四阶流水线后，实际在微端与 Web 控制台联调中暴露出以下关键问题：
1. **全员避让滞后致微端无法登录**：此前避让使用的是异步优雅关闭（`active_client.disconnect()`），在 Windows 下受操作系统 TCP 缓冲区与 FIN-WAIT 影响滞后数秒至十几秒，后台常驻守护协程仍保持休眠未即刻销毁，导致官网网关仍判定角色在线，微端被频繁顶号。
2. **长连接默认未启用致全员恢复为 0**：数据库 `data/config.sqlite` 存量账号的 `hosting_enabled` 为 0，导致服务启动无法自动拉起长连接托管，且【全员恢复】因严格检查 `acc.hosting_enabled` 直接跳过了所有账号。
3. **状态脱节与态势未自动更新**：前端缺少定时轮询自愈机制，未监听底层避让解除事件，导致卡片运行态标签（“托管在线中 / 离线 / 未连接”）没有随网络状态实时变动；全景态势也缺乏常规默认定时抓取。
4. **背包自理保守策略受限**：此前流水线因对体力丹与自选宝箱过于谨慎，遇到满载背包（如小号 48 格全满）无法彻底腾空，导致常规扫荡与新道具入包依然受阻。

## 决策内容

### 1. 强杀式防互踢避让 (Hard Abort Evade)
- **底层强杀**：在 `SXDClient` 中新增 `abort()` 方法，直接通过底层 `transport.abort()` 向操作系统协议栈发送 TCP RST 报文，强制瞬间切断 TCP 物理通道。
- **协程立即销毁**：`trigger_evade` 执行时，立即 `cancel()` 该账号绑定的 `_hosting_tasks`，不再让其在后台继续休眠或退避重试；重置连接态为 `disconnected`，确保 0.1 秒内释放游戏网关会话，微端秒登无阻。

### 2. 全量长连接默认启用与全员恢复兜底
- **存量迁移**：启动时自动检测并执行数据库升级，将所有 `enabled=1` 账号的 `hosting_enabled` 强制置为 `1`。
- **全员恢复兜底**：`resume_all()` 对全部已启用账号统一将 `hosting_enabled` 设为 `True`，清除 `evade_state`，并立即调用 `start_hosting(alias)` 重新建立长连接，确保 100% 唤醒。

### 3. 前端动态实时跟随与默认态势定时抓取
- **状态感知增强**：`get_session_info()` 以真实 `client and client.context.is_connected` 判定连接状态，杜绝伪在线；完善 SSE 事件监听并在前端挂载 5 秒自动状态轮询。
- **态势定时抓取**：后台常驻守护增加中频定时态势巡检（每 180 秒执行一次 `query_all` 并推流），保持伙伴、装备与背包数据始终最新。

### 4. 激进背包清空流水线与独立使用功能
- **四阶激进清包**：
  1. 第 1 阶：调用 `classify_pack` 整理归纳；
  2. 第 2 阶：能打开的都打开（固定宝箱全开、自选宝箱默认开、体力丹直接吃满、经验丹全吃）；
  3. 第 3 阶：无法打开的材料移入随身仓库；
  4. 第 4 阶：随身仓库满后，背包剩余物品全量变卖换钱，无法变卖的彻底丢弃（Mod 2 Act 46），保证背包彻底腾空。
- **独立一键使用物品功能**：抽屉面板新增【一键使用物品】按钮，仅跑第 1~2 阶（整理+开箱/吃丹），不存仓不丢弃，供日常无损减负。

## 影响评估
- **积极影响**：
  - 微端上线 100% 不再冲突，避让秒级生效；全员恢复一键唤醒全部账号。
  - 背包空间无论多满均可按用户意愿彻底腾空，从根源消除扫荡卡死。
  - 前端界面状态与实际物理长连接 100% 实时同步。
- **权衡与注意点**：
  - 激进清空中仓库满后剩余物品将被彻底丢弃（Mod 2 Act 46 不可逆），用户界面需提供二次确认强提示。
